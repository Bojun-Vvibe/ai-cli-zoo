# yt-dlp

> **The de facto media-extractor CLI** — a single Python script
> (shipped as a self-contained binary) that downloads audio,
> video, subtitles, thumbnails, and metadata from ~1800+ websites
> (YouTube, Vimeo, Twitch, SoundCloud, BBC iPlayer, Bilibili, NHK,
> arXiv talks, podcast hosts, university lecture portals, …) and
> exposes a *format-selection language* (`-f
> "bestvideo[height<=1080]+bestaudio/best"`) that lets you pick
> the exact resolution / codec / container without re-encoding.
> Pinned to **2026.03.17** (commit
> `7fd74d10097833ebce0cb162e0ccf7825de9b768`,
> [LICENSE](https://github.com/yt-dlp/yt-dlp/blob/2026.03.17/LICENSE),
> Unlicense / public domain).

Source: <https://github.com/yt-dlp/yt-dlp>

## TL;DR

`yt-dlp` is the actively-maintained successor to `youtube-dl`,
forked when upstream went dormant in 2020. It's the same shape
(one CLI, URL → file) but with a much faster release cadence
(roughly monthly), broader site coverage, smarter default format
selection, native SponsorBlock integration, an embedded chapter
parser, and an extension surface (extractor plugins, post-processor
plugins) that lets a small change land without waiting on a core
release. For a coding-agent workflow, it's the canonical "I have
a video URL and need the audio file / a transcript / a 720p MP4"
primitive — pipe its `--print` JSON output into `jq` and any
downstream LLM CLI gets a clean structured handle on the media.

## Install

```bash
# Homebrew (macOS / Linux)
brew install yt-dlp

# pipx (recommended for Python users — isolates dependencies)
pipx install yt-dlp

# pip
python3 -m pip install -U yt-dlp

# Self-contained binary (no Python needed)
curl -Lo yt-dlp "https://github.com/yt-dlp/yt-dlp/releases/download/2026.03.17/yt-dlp"
chmod +x yt-dlp
sudo install yt-dlp /usr/local/bin/

# Linux package managers
# Arch:    pacman -S yt-dlp
# Fedora:  dnf install yt-dlp
# Nix:     nix-env -iA nixpkgs.yt-dlp

# Strongly recommended companion for muxing / re-encoding / thumbnail embedding
brew install ffmpeg

# verify
yt-dlp --version    # 2026.03.17
```

## One Concrete Example

```bash
# 1. simplest possible: best quality available, save to current dir
yt-dlp "https://www.youtube.com/watch?v=dQw4w9WgXcQ"

# 2. audio only, MP3 (uses ffmpeg to remux + convert)
yt-dlp -x --audio-format mp3 --audio-quality 0 "<URL>"

# 3. specific format: 1080p MP4, separate audio merged in
yt-dlp -f "bestvideo[height<=1080][ext=mp4]+bestaudio[ext=m4a]/best[height<=1080]" "<URL>"

# 4. list available formats first, then pick one
yt-dlp -F "<URL>"
# ID  EXT   RESOLUTION  FPS  | FILESIZE   PROTO | VCODEC       VBR    ACODEC      ABR
# 251 webm  audio only       |  3.62MiB   https | audio only          opus      160k
# 137 mp4   1920x1080   30   | 45.20MiB   https | avc1.640028  4500k  video only
# ...
yt-dlp -f 137+251 "<URL>"

# 5. subtitles + autogenerated captions, embed into the video
yt-dlp --write-subs --write-auto-subs --sub-langs "en,en-orig" \
       --convert-subs srt --embed-subs "<URL>"

# 6. download a whole playlist with structured filenames + metadata sidecars
yt-dlp -o "%(playlist_title)s/%(playlist_index)03d - %(title)s.%(ext)s" \
       --write-info-json --write-thumbnail \
       "https://www.youtube.com/playlist?list=PL..."

# 7. JSON metadata only (no download) — perfect for piping into jq / LLMs
yt-dlp --skip-download --print-json "<URL>" | jq '{title, duration, uploader, chapters}'

# 8. SponsorBlock — skip / mark sponsor segments, intros, outros
yt-dlp --sponsorblock-mark all --sponsorblock-remove sponsor,selfpromo "<URL>"

# 9. archive mode — track what's been downloaded; skip on re-run
yt-dlp --download-archive ~/.yt-dlp-archive.txt \
       "https://www.youtube.com/@some-channel/videos"

# 10. cookies for age / region / login-gated content (export from browser)
yt-dlp --cookies-from-browser firefox "<URL>"
```

## Niche It Fills

**Polyglot media extraction as a stable Unix-pipeable CLI.** Every
site invents a different player, DRM scheme, manifest format
(HLS / DASH / progressive MP4 / WebM), and rate-limiter; `yt-dlp`
abstracts all of them behind one URL → file interface with a
single uniform format-selection grammar and a single uniform
metadata schema. For an agent workflow, this is the cheapest path
from "user dropped a YouTube / podcast / lecture URL" to "I have
the audio and a transcript ready to feed the LLM" — `yt-dlp -x
--audio-format mp3` plus `whisper.cpp` (already cataloged) covers
the entire pipeline in two commands.

## Why use it

Three things `yt-dlp` does that ad-hoc curl / browser-extension
solutions do not:

1. **Format-selection language as a first-class API.** `-f
   "bestvideo[height<=720][vcodec^=avc1]+bestaudio[ext=m4a]"`
   reads like an SQL filter, composes with sort
   (`-S "res:720,fps,vbr"`), and is identical across all 1800+
   sites. You learn the grammar once and it works on a Twitch VOD
   the same way it works on a YouTube live recording. `-F` lists
   available formats; `--print-json` gives the full schema.
2. **Plugin / extractor architecture for the long tail.** Sites
   change their player monthly and break extractors; `yt-dlp`'s
   release cadence (~monthly) catches most of these, and for
   urgent fixes you can drop a single Python file into
   `~/.config/yt-dlp/yt-dlp/plugins/` to override or add an
   extractor without touching the install. Post-processor plugins
   let you slot in custom subtitle cleaners, thumbnail croppers,
   or metadata enrichers in the same file.
3. **Structured metadata sidecar for downstream tools.** Every
   download can emit a `.info.json` with the full upload metadata
   (title, uploader, duration, chapters, view count, upload date,
   subtitles), a `.description` text file, a thumbnail image, and
   `.live_chat.json` for streams that had chat. Downstream tools
   (database loaders, RAG indexers, the LLM you're piping
   transcripts into) get clean structured handles without
   re-scraping the source page.

## Vs Already Cataloged

- **Vs [`whisper.cpp`](../whisper.cpp/):** complementary —
  `yt-dlp` extracts the *audio file* from a URL; `whisper.cpp`
  transcribes that audio file to text. The standard pipeline is
  `yt-dlp -x --audio-format wav <URL> -o /tmp/a.wav && whisper.cpp
  -f /tmp/a.wav -otxt`. Neither tool tries to do the other's
  job — they compose cleanly via the filesystem.
- **Vs [`monolith`](../monolith/):** orthogonal — `monolith`
  archives a *web page* (HTML + inlined CSS/JS/images) into one
  self-contained `.html` file; `yt-dlp` extracts *media payloads*
  from a page (the actual video/audio bytes, not the surrounding
  HTML). For a YouTube URL, `monolith` would give you a snapshot
  of the page chrome; `yt-dlp` gives you the video itself.
- **Vs [`crawl4ai`](../crawl4ai/) / [`firecrawl`](../firecrawl/):**
  orthogonal — those are LLM-friendly *web-content* extractors
  (HTML to clean Markdown for context); `yt-dlp` is a *media*
  extractor (URL to MP4 / MP3 / VTT subtitles). Use crawl4ai for
  text articles, `yt-dlp` for video / audio / podcast / lecture
  content.
- **Vs `youtube-dl` (the upstream, not cataloged):** direct
  successor — `yt-dlp` is faster (concurrent fragment downloads
  for HLS/DASH), has more extractors, ships SponsorBlock and
  chapter integration, and releases monthly vs upstream's
  sporadic-to-dormant cadence. The CLI surface is a strict
  superset; existing `youtube-dl` scripts work unchanged.
- **Vs `gallery-dl` (not cataloged):** complementary — `gallery-dl`
  specializes in *image-set* sites (Imgur, Twitter / X media,
  Pixiv, DeviantArt, Tumblr, Instagram); `yt-dlp` specializes in
  video / audio. Some overlap on social-media video posts, but
  `gallery-dl`'s metadata model is image-gallery-shaped while
  `yt-dlp`'s is video-shaped.

## Caveats

- **Sites change; extractors break.** A YouTube player update or
  Twitch UI rewrite can break extraction overnight. The fix is
  almost always `yt-dlp -U` (self-update) or a fresh `pipx upgrade
  yt-dlp` — but if you're on a pinned version (corporate package
  repo, frozen container) you may need to wait or pull a master
  build via `python3 -m pip install -U
  "git+https://github.com/yt-dlp/yt-dlp@master"`.
- **`ffmpeg` is a soft dependency for half of usefulness.** Format
  merging (separate video + audio streams), audio extraction,
  thumbnail embedding, subtitle conversion, and live-stream
  recording all require `ffmpeg` on the PATH. Without it, `-f
  bestvideo+bestaudio` either picks a single combined format
  (lower quality) or errors out.
- **Cookies / login matter for age / region / member content.**
  `--cookies-from-browser firefox` works once you've logged in via
  the browser; `--cookies cookies.txt` reads a Netscape-format
  file. For non-interactive CI, exporting + securely storing the
  cookie file is a real operational concern. Ship-of-Theseus
  warning: long-lived cookies are also fragile and may expire mid
  job.
- **Rate limits + IP bans are real.** Hammering a single site from
  one IP will get you a 429 or a captcha gate. `--sleep-interval`,
  `--max-sleep-interval`, `--limit-rate`, and rotating proxies
  (`--proxy`) exist for a reason; for archival work, stay polite.
- **Legal scope is on you.** `yt-dlp` happily downloads anything
  it can extract; whether you're allowed to *keep* or
  *redistribute* the result depends on the source site's terms,
  the content's copyright, and your jurisdiction. The tool ships
  with `--no-overwrites` and archive tracking, not with a
  copyright lawyer.
- **Default output template is fine, but unique-filename hygiene
  matters at scale.** The default `%(title)s [%(id)s].%(ext)s`
  embeds the platform's stable ID, which is the right thing for
  archives. Custom templates that drop the ID will collide on
  duplicate titles; learn `-o "%(uploader)s/%(upload_date)s -
  %(title)s [%(id)s].%(ext)s"` early.
