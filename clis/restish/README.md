# restish

> **A generic, OpenAPI-aware HTTP client for the
> command line** — point it at a base URL (or an
> OpenAPI 3 / OpenAPI 2 / JSON Schema document)
> and it auto-discovers operations, generates
> short subcommands, handles auth profiles
> (HTTP Basic, API key, OAuth2 client-credentials
> / authorization-code with PKCE, AWS SigV4,
> external token-getter), negotiates content via
> `Accept`, decodes JSON / CBOR / MessagePack /
> Ion into the same in-memory tree, and pretty-
> prints with syntax highlighting. Pinned to
> **v0.21.2**
> ([LICENSE.md](https://github.com/rest-sh/restish/blob/main/LICENSE.md),
> MIT).

Source: <https://github.com/rest-sh/restish>

## TL;DR

`curl` is a *transport* — you write the URL, the
verb, the headers, the auth header, the body, and
the query string yourself, every single time. For
a one-off probe that's fine; for repeated work
against the same API it's pure tedium and a
constant source of typos. `restish` is the layer
above: you register an API once
(`restish api configure example`), point it at a
base URL plus optional OpenAPI document, and from
then on the API's operations show up as
subcommands (`restish example list-things`,
`restish example create-thing < body.json`). Auth
flows are configured per-profile, tokens are
cached, and every response is parsed into a
typed tree so you can pipe straight into `jq` /
`jp` / `gron` without re-quoting JSON. It is
`curl` if `curl` had read your API spec first.

## Install

```bash
# Homebrew (macOS / Linuxbrew)
brew install danielgtaylor/restish/restish

# Go install (any platform with Go ≥ 1.21)
go install github.com/danielgtaylor/restish@v0.21.2

# Pre-built binaries from the release page
curl -L -o /tmp/restish.tar.gz \
  https://github.com/rest-sh/restish/releases/download/v0.21.2/restish-0.21.2-linux-amd64.tar.gz
tar -xzf /tmp/restish.tar.gz -C /usr/local/bin restish

# verify
restish --version    # restish version 0.21.2
```

`restish` is a single static Go binary with no
runtime dependencies — drops into Alpine /
distroless / scratch images cleanly.

## Use it for

```bash
# 1) Treat any URL as a one-shot client (no API config needed)
restish https://api.github.com/repos/rest-sh/restish

# Equivalent to curl, but with content negotiation, pretty-print,
# and parsed-tree output you can pipe to jq / jp.
restish https://api.example.com/v1/users \
  --rsh-filter 'body.items[?status == "active"].id'

# 2) Register an API once, then call by short name
restish api configure example
#   → prompts for base URI, optional OpenAPI doc, auth scheme

restish example                       # lists discovered operations
restish example list-users            # auto-derived subcommand
restish example get-user --id 42      # path/query params from spec
restish example create-user < body.json

# 3) Switch auth profiles for the same API (prod / staging / mine)
restish -p staging example list-users
restish -p prod    example list-users

# 4) OAuth2 + PKCE flow — token caching handled for you
restish api configure my-saas
#   → choose "oauth-authorization-code"
#   → restish opens browser, captures token, persists in cache

# 5) Edit a resource in $EDITOR (GET → edit → PUT round-trip)
restish edit example get-user --id 42

# 6) Headers / query / body shortcuts (HTTPie-style)
restish post https://api.example.com/v1/users \
  Authorization:"Bearer $TOKEN"  \
  name=alice  role=admin  tags:='["a","b"]'
```

Profiles, headers, and discovered operations live
in `~/.restish/apis.json`; tokens cache in
`~/.restish/`. Bash / zsh / fish completions are
generated by `restish completion <shell>`.

## Why include it in a CLI catalog

1. **OpenAPI-aware HTTP CLIs are rare.** Almost
   every HTTP CLI in this catalog
   (`curl`, [`xh`](../xh/), [`httpie`](../httpie/),
   [`curlie`](../curlie/), [`hurl`](../hurl/)) is
   a pure transport — you supply the operation
   shape every time. `restish` reads OpenAPI 3,
   OpenAPI 2, or JSON Schema and exposes
   operations as native subcommands with typed
   parameters and inline help. For LLM-driven
   workflows that hit the same SaaS REST API
   repeatedly, this collapses N curl invocations
   into N short, completable subcommands.
2. **Real auth, not just headers.** OAuth2
   client-credentials *and* authorization-code
   with PKCE, AWS SigV4, HTTP Basic, API key,
   and external token-getter command (so you can
   plug in any vendor SDK that emits a token).
   Tokens cache and refresh transparently — no
   more pasting bearer tokens into every `curl`.
3. **Content negotiation that actually works.**
   Sends a sensible `Accept` header, decodes
   JSON / CBOR / MessagePack / Ion / YAML into a
   single in-memory representation, and re-emits
   in your preferred format
   (`--rsh-output-format json|yaml|ion`). For
   APIs that speak multiple wire formats, the
   shape stays the same regardless of what came
   back over the wire.

For an LLM-CLI workflow, `restish` is the
"discoverable HTTP layer" piece: feed the model
`restish example --help`, it sees the actual
operations the API exposes, and emits invocations
that round-trip through real auth — no hand-rolled
curl strings, no leaked bearer tokens in shell
history. Pairs naturally with [`jq`](../jq/) /
[`jp`](../jp/) / [`gron`](../gron/) on the
response side.

## Vs Already Cataloged

- **Vs [`curl`](../curl/) / [`xh`](../xh/) /
  [`httpie`](../httpie/) / [`curlie`](../curlie/):**
  orthogonal layer. Those are pure HTTP transports
  — you specify the URL, method, headers, body
  every call. `restish` is a *client* that reads
  OpenAPI / JSON Schema and turns operations into
  subcommands; for ad-hoc probes you can still
  fall through to URL mode.
- **Vs [`hurl`](../hurl/):** different paradigm —
  `hurl` is for *recorded test sequences*
  (request → assertion → next request) checked
  into git. `restish` is for *interactive +
  scripted single calls* against discovered
  operations.
- **Vs [`posting`](../posting/) /
  [`atac`](../atac/) / [`bruno`](../bruno/) /
  [`slumber`](../slumber/):** those are TUIs /
  GUIs / collection-based clients (Postman-style).
  `restish` is one-shot, batch, scriptable, and
  driven by the API's own machine-readable spec.
- **Vs [`gh`](../gh/) / vendor CLIs:** `restish`
  is generic — *any* OpenAPI-described API gets
  the same treatment. You don't wait for a vendor
  to ship a CLI; if they publish a spec, you have
  one.

## Caveats

- **OpenAPI is optional but recommended.** Without
  a spec you still get HTTPie-style URL-mode
  invocations + auth-profile + pretty-print, but
  no operation auto-discovery, no completion of
  parameter names, no per-op help.
- **Quality of the auto-generated subcommands
  tracks the quality of the OpenAPI doc.**
  Underspecified `operationId`s, missing
  `description`s, or schema-less request bodies
  produce flat subcommand names and free-form JSON
  body parameters. `restish` is a faithful
  surface, not a fixer.
- **Token cache lives on disk** in `~/.restish/`.
  On shared machines treat it like an SSH key —
  `chmod 700 ~/.restish`. No secret-management
  integration ships in-box; for vault-style flows
  use the `external-tool` auth scheme and point at
  your own getter.
- **Repository moved orgs in 2024 from
  `danielgtaylor/restish` to `rest-sh/restish`.**
  The Go module path remains
  `github.com/danielgtaylor/restish` for
  compatibility, so `go install` still works
  unchanged. Both URLs resolve.
- **MIT license** — permissive; safe to embed in
  proprietary container images and CI runners
  with attribution.
